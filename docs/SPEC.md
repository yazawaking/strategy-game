## 1. 最重要の設計意図

> リアルタイムで戦況が動く面白さを残し、ちょこまか指を動かさず、戦略に徹して遊べるようにする。

- プレイヤーが主攻・目標・予備・補給路・CP投入を決め、動く戦線を見届けることが中心。「簡単にする」「敵AIを止める」「ターン制に戻す」と同義ではない
- 時間は連続して進む。考えている間は手動停止でき、重大な危機だけ任意の自動停止が入る。**一定時間ごとの強制「実行」ループは採用しない（v5ターン制は廃止済み）**
- 味方の任務AIは新しい戦略目標を勝手に選ばず、CPも自動消費しない。この境界が指揮の手応えを残す

## 2. 技術構成と実行境界

### 2.1 単一ファイル構成

- `<!doctype html>` / `lang="ja"` / UTF-8。CSSは`<style>`、アイコンは埋め込みSVG `<symbol>`、図形はCanvas 2D、効果音はWeb Audio API
- 外部script・stylesheet・画像・フォント・API通信は不要。ビルドも不要。配布ファイル名は `index.html` のまま保つ（画面内ダウンロードリンクが `./index.html` を指すため）
- `script#engine`（77〜693行）と `script#interface`（695〜1083行）を分離。どちらも通常のインラインscript（ES module 不要）

| 層 | 責務 | 公開 |
| --- | --- | --- |
| engine | 決定的シミュレーション（`PocketBlitz` IIFE）。DOM・Audio・rAF・localStorageを一切使用しない | `globalThis.PocketBlitz` |
| interface | Canvas描画・入力・UI・localStorage・音声。`const B = PocketBlitz` でエンジンを使用 | IIFE内に閉じ、`game` 等をグローバル公開しない |

### 2.2 画面（SPA）

| 画面ID | 内容 |
| --- | --- |
| `screen-setup` | 地図プレビュー、難易度、ドクトリン、作戦案、シード、記録、再開 |
| `screen-game` | トップ情報、任務・部隊・スキル、地図、進行ボタン。開始直後は停止 |
| `screen-report` | 途中経過または勝敗・KPI・再戦。開くと停止 |

- `.screen.active` だけを表示。`changeScreen()` がclassと `aria-hidden` を切替、画面遷移時に時間を止める
- dialog: `help-dialog` / `plan-dialog` / `roster-dialog`。開く際に停止し、閉じても勝手に再開しない

### 2.3 状態の分離

| 層 | 主な状態 | 永続化 |
| --- | --- | --- |
| エンジン | 地図・部隊・任務・CP・損害・勝敗 | `serialize()` の対象 |
| UI | 選択部隊・speed・pace・カメラ・Undo | メモリのみ |
| 演出 | パーティクル・浮動文字・音声 | 戦闘計算に含めない |
| 保存 | 中断作戦・戦績・音声設定 | localStorage |

**不変の境界: エンジンにDOM/Audio/rAF/localStorageを持ち込まない。戦闘計算に描画フレーム数や演出乱数を入れない。**

## 5. 座標系とマップ生成

### 5.1 六角形（Pointy-Top Odd-R）

```js
id(c,r) = r*13 + c
x = 40 + (c + (r & 1) / 2) * sqrt(3) * 32
y = 40 + r * 32 * 1.5
mirror(c,r) = { c: 12 - c - (r & 1), r: 8 - r }
```

- 単純な `12-c` 鏡映は正しくない。盤外セルは描画/経路/隣接から除外するが配列からは取り除かない
- 隣接方向は偶数行・奇数行で異なるテーブル。距離はaxial変換して `max(|dq|,|dr|,|dq+dr|)`

### 5.2 公平性・再現性

- 乱数は `hash(seed + '|' + map)` による固定実装の32bitハッシュ+PRNG。戦闘進行にPRNGは使わない
- 初期所有は `x = c + (r&1)/2 - 6` で x≤−1=ALLY、x≥1=ENEMY、中央中立。首都はALLY`(1,4)` / ENEMY`(11,4)`、中立中継拠点は `(5,1)`, `(6,4)`, `(6,7)` 固定
- 地形生成は回転対称セルへの複製→閾値で森林/山岳→通路の山岳置換→都市配置→到達不能島の山岳化→中央鉄道敷設→配置の順。鉄道経路自体も回転対称化する
- **地形生成の乱数消費順やアルゴリズムを変えると、同じseedでも別地図になり旧セーブの復元に影響する。重要な互換性境界**

### 5.3 初期戦力（両軍とも11師団・完全対称）

| グループ | 構成 | 人数（通常ドクトリン） |
| --- | --- | ---: |
| LINE | 歩兵4＋自走重砲1 | 47,000 |
| HQ | 歩兵1 | 10,000 |
| NORTH / SOUTH | 機甲1＋自動車化1（ずつ） | 17,000 ずつ |
| RESERVE | 機甲1（FIREPOWERでは重砲1） | 8,000（火力では7,000） |

通常合計99,000人／火力98,000人。ドクトリンの構成・効果は**両陣営に適用**（自軍だけのボーナスはない）。

## 7. 連続時間・停止

### 7.1 時間の責務

- `B.step(state)` が厳密に1ゲーム時間を進める。エンジンは実時間を知らず、UIの単一RAFループが累積dtでstepを呼ぶ
- `interval = 700 / speed`（×1=700ms/tick、×2=350ms/tick）。dt上限100ms、1フレームのtick上限4
- 任務定期再評価＝6ゲーム時間ごと、敵AI再判断＝全難易度12ゲーム時間ごと。期限判定はtick増加前に行われる（初回AI判断はtick12→13のstep）

### 7.2 1tickの処理順

1. 終了済みなら何もしない
2. 期限到来時 敵AI → 任務更新
3. tick+1。電撃戦残時間減算、12時間ごとにCP回復
4. `intentions()` で攻撃・拘束の再構築
5. rest減算、ORG回復／途絶中の消耗
6. 通常移動 → 補給再計算
7. 全戦闘の損害を**同時集計・一括適用**、退却・壊滅・進出
8. SAFEの安全後退 → 補給再計算
9. 勝敗判定・危機通知
10. UIがイベント表示し、勝敗またはpauseRequestで停止

`step(s,{ai:false})` はテスト用で、敵AIと味方任務の再評価を両方止める（物理・戦闘は進む）。

### 7.3 手動・自動停止

- Space／ボタンでいつでも停止・再開。設定・レポート・dialog・`visibilitychange`・`blur` でも停止。再開は手動
- 危機停止（初期ON）: ①首都喪失または首都から距離2以内の敵、②2部隊以上の新規補給途絶。重複防止は12時間のクールダウン
- 移動完了・拠点確保・日付変更・通常戦闘では停止しない。自動停止の実行主体はUI（エンジンは `pauseRequest` を出すだけ。ヘッドレスのstep連打は停止しない）

## 8. 移動・経路・拘束

### 8.1 findPath（Dijkstra）

戻り値は開始地点を含まないセルID配列。到達不能なら空配列。コスト=進入地形cost、敵部隊占有+14、移動中味方+2.5、待機中味方+7。オプション: `avoidEnemy`（敵占有マス除外）、`ownedOnly`、`terrainOnly`（cost1・占有コストなし）。小規模盤面のためヒープ不使用。

### 8.2 移動進捗

```
進捗増分 = spd × 1.25 ÷ 進入先cost
補給途絶: ×0.30 ／ 電撃戦中のARM/MOT: ×1.65
move >= 100 で移動し move=0（超過分は繰り越さない）
```

1マス目安（×1、平地・補給下）: INF 16.1秒 / ARM 8.4秒 / MOT 7.0秒 / SPG 11.9秒。
移動処理順は `hash(tick + ':' + unit.id)` で並べる（常に先頭陣営が先に動くのを避ける。確率乱数ではない）。

### 8.3 占有と交通整理

- 1セル1部隊・スタック不可。敵のいる次マスは通常移動せず攻撃関係を作る
- 味方同士の位置交換は非拘束・非再編成のときに限り、遅い側の速度で進捗をためて実現
- 味方占有ではwaitを増やし、8回待ち＋残ルート2マス以上なら再探索を試みる
- 次マスが隣接でない／進入不可なら `halt()`（任務も解除する経路防御。壊れたpathは黙って進めない）

### 8.4 攻撃意思・pinning

- `intentions()` が全attack/pinnedを消してpathから再構築。次マス隣接敵＋ORG>8＋rest=0 で攻撃対象に設定し、防御側をpinned化
- 拘束された部隊は「空いた自軍所有マスへの移動」だけ可能。敵領抜け・味方交換・敵への通常進出は不可
- 迂回任務の未確保段階は正面攻撃しない（`defendingMission` の局所防御反応は例外）

## 9. 補給・急所・ポケット

### 9.1 補給の成立

- 自軍の**本来の首都**を自軍所有していることが起点。そこから山岳・盤外以外の自軍所有セルをBFS。中立・敵領・敵に占領された自首都ではつながらない
- 占領した敵首都は新補給源にならない。都市・中継拠点も補給を新規発生させない。鉄道はBFS探索順の優先だけで容量・距離減衰はない
- 補給線表示は「利用可能な接続の一例」であり、その線の途中1マスを取っても必ず切れるとは限らない

### 9.2 急所（criticalTiles）

- 表示の破線の太さではなく、**セルを遮断した仮定でのBFS再実行**で確認した実接続に基づく急所。`{cell, count, ids}` を返す
- 地図バッジは count≥2 かつ無人セルのみ。MASTERの敵AIはこれを狙う

### 9.3 途絶ペナルティとポケット

| 効果 | 値 |
| --- | ---: |
| 攻撃・防御・移動 | ×0.30 |
| ORG | 毎tick −1.3（非戦闘の途絶処理では下限2） |
| 兵力 | cutHours>6 から STR −0.1/tick（STR5%を下限に不可） |

- ポケット: 補給途絶の自軍領地の連結成分にIDを付与。合流時は累計撃破兵員を統合、分裂の厳密な再分配は未実装
- `maxPocket` = 同じ孤立地域IDで包囲壊滅した**残存兵員の累計**（初期人数や通常戦闘損失は含めない）
- 補給回復で cutHours/pocket リセット。兵力は自然回復しない。ORGは補給＋非交戦で 都市/首都+2.1、その他+1.4/tick

## 10. 戦闘計算

### 10.1 攻撃力・防御力

```
attack = atk × (str/100) × (0.45 + 0.55 × org/100)
         × (ARMなら terrain.armor)
         × (途絶 0.30) × (電撃戦・INF以外 1.45) × (浸透の夜間INF/MOT 1.12)
flank = 1 + (参加数-1) × (FIREPOWER ? 0.38 : 0.30)
defense = def × (str/100) × (1 + 補給あり×地形def[SPG参加なら地形def無効]) × (途絶 ? 0.30 : 1)
ratio = totalAttack × flank / max(2, defense)
```

ORG8以下では新規の攻撃意思を作らない。

### 10.2 損害（ソース照合済みの式）

```
防御側ORG損失 = min(10, 1.65 × ratio^1.18) × (siege ? 1.15 : 1)
防御側STR損失 = 防御側ORG損失 × 0.15
攻撃側損失(基礎) = min(5, 1.25 / max(0.30, ratio)) / 攻撃参加数
攻撃側ORG損失 = 基礎 × 18 / brk【BLITZのARMは brk×1.25】
攻撃側STR損失 = 基礎 × 0.095
```

- 損害はMapに集計し**全戦闘分を集めてから適用**（先制優位の排除）。相互攻撃・複数戦闘は合算
- ORG0は通常退却、STR0は壊滅（下限10%ではない）

### 10.3 退却・壊滅・進出

- 退却先=通行可・自軍所有・空き隣接セル（補給なし+20、隣接敵×3、首都距離のスコア選好）
- STR>0で退却可→即時後退（ORG23、rest8、処理中フラグ）。STR0または退却先なし→削除
- 削除時が補給途絶かつSTR>0→**包囲壊滅**: 残存兵員を包囲損害に計上し相手側へ+14 CP
- 空いたセルへはORG>8・rest=0・未pinnedの攻撃者が進出可（ORG高者優先）。進出後に所有更新
- 戦闘バブルの数値は優劣スコア（1〜99）であり勝率ではない。表示しきい値: ≥65緑 / <38赤

## 11. 安全後退と任務

### 11.1 SAFEの予防後退

SAFE・0<ORG<30・rest=0・攻撃/被攻撃の部隊は、補給中の自軍空きセルへ即時後退（1tickで隣接へ。退路がなければ放置）。敵も同じルール。

### 11.2 任務システム

| 種別 | 接近・戦闘 | 確保後 |
| --- | --- | --- |
| CAPTURE 制圧 | 目標の防衛者を分散攻撃 | 目標中心の守備 |
| FLANK 迂回 | 敵占有セルを回避 | 確保地域の守備 |
| DEFEND 防衛 | 指定地点展開・近接敵に対応 | 遠い敵を追わず維持 |
| MANUAL（UI選択値） | 継続任務なし・直接移動 | 停止していれば待機 |

- `assignMission()` はCP不消費・戦闘中でも可。`halt()` は通常任務も解除（退却内の `halt(uid,false)` は任務を保つ）
- 確保判定は「所有＋部隊接近」。確保後も次の戦略目標を自動選択しない
- 優先順: 生存部隊抽出 → 確保判定 → 回復処理 → 局所支援・反撃 → 目標が敵占有なら多方向攻撃 → 配置候補への分散
- 配置は目標＋隣接（必要なら2リング目）。**自首都に最も近い隣接自軍セルを1つ駐留から外し、包囲側の退却不能化を防ぐ**
- 近接支援は火力比≥0.95など条件つき。任務外の目標へ勝手に進まない
- 回復: rest>0で保留 → SAFE/ORG<30・PRESS/ORG<8でrecovering → 補給ありORG≥60で復帰 → 同任務・同目標へ復帰

## 14. 勝敗・評価・戦績

### 14.1 終了条件

1. 両軍0部隊 → DRAW ／ 敵0部隊 → ALLY勝利 ／ 自軍0部隊 → ENEMY勝利
2. それ以外は首都保持判定。敵首都セルが ①自軍所有 ②自軍補給下 ③自軍部隊駐留 ④部隊ORG>8 ⑤非pinned の全条件を満たすtickごとに `holds` +1。**1つでも崩れると0に戻る。24に達すると勝利**。同時達成はDRAW
3. 敵首都を一時的に触れただけでは勝てない（補給下での24時間保持が必要）。終了後 `step()` は何もせず、命令・スキルも無効。途中レポートからは復帰できるが、確定リザルトからは再戦または新作戦のみ

### 14.2 KPIとスコア

```text
敵総損失 = kpi.combat + kpi.pocket
K/D = 敵総損失 / loss.ALLY（自軍損失0かつ敵損失>0はInfinity、両方0なら0）
包囲率 = kpi.pocket / 敵総損失（敵損失0なら0）
```

| 軸 | 最大点 | 条件 |
| --- | ---: | --- |
| 速度 | 40 | tick≤180: 40 / ≤300: 25 / それ以降10 |
| K/D | 35 | ≥5: 35 / ≥2.5: 20 / それ未満10 |
| 包囲率 | 25 | ≥0.5: 25 / ≥0.25: 15 / それ未満0 |

勝利時: 80点以上S、55点以上A、それ未満B。敗北C、DRAWはB。評価は内部の比率値（表示丸め値ではない）。停止中の実時間は評価に入らない。

### 14.3 戦績

- `map|ai|doc` をキーに最高rank・最小hours・最大kdを個別保存（seed/planはキーに含めない。複数回の最良達成の集まりであり1回の作戦記録ではない）
- 勝利時のみ更新。Infinity はJSON互換のため文字列 `"Infinity"` で保存

## 15. 保存形式・互換性

### 15.1 キーと保存時機

| キー | 値 |
| --- | --- |
| `pb_operation_v6` | serializeした現在作戦（1枠） |
| `pb_records_v6` | 条件別戦績JSON |
| `pb_sound_v4` | `on`/`off`（音量キーは旧名称を継続） |

命令成功・停止・スキル・posture・作戦案・危機設定・画面離脱で保存。進行中は前回保存から12時間以上経過時。ページ再読み込み後は停止状態から再開（速度は復元しない）。

### 15.2 serializeの範囲と注意

- 地形・鉄道・initialOwnerは保存せず、configから `scenario()` で再生成。保存する地図差分は `owners` のみ。補給・経路・cache・bubblesは再計算する
- 戦闘は決定的なので、同version・同configならセーブからもとの未来を正確に再生できる
- **地形生成アルゴリズムを変更してもversion=6のままにすると、旧セーブが別の地形へ復元される危険がある。生成バージョンや互換性方針を決めてから変更する**

### 15.3 restore

- versionは4/5/6を許可。UIは `pb_operation_v6` → `v5` → `v4` の順に探す
- units・owners長117・兵科/陣営/座標/ID重複・ORG/STR範囲・path連続性・tick/CP範囲・任務参照を検査。読み込み後に補給と攻撃意思を再構築
- 完全なスキーマ検証ではない（汎用的な破損防御）。外部インポート機能を追加する前に補強すること
- 旧データは位置・兵力・CP・path等を保持して移行。旧ターンのphase/remainingは再実行しない。旧キーは削除しない

## 17. 実装上の既知の注意点（重要度順）

1. **地形生成を変えると同seedで別地図になる**。旧セーブ影響と互換性方針（生成バージョン等）を先に決める
2. **保存形式を破壊的に変える場合**、versionを上げ、restore側の旧形式受け入れと移行処理を一緒に入れる
3. 損害は「全戦闘分を集めてから一括適用」。resolve内の順序変更は先制優位の再導入や同時性の崩れにつながるため慎重に
4. `step({ai:false})` は味方任務の定期再評価も止める。AI動作の回帰検証には使えない
5. 補給表示の破線の太さ≠急所。急所は `criticalTiles()` の仮定遮断BFSのみが正根拠
6. ポケット関連（`pockets`/`nextPocket`/`kpi.maxPocket`）は分裂・合流の処理が簡略化されている。評価を扱う変更の前に挙動を確認する
7. CSSにv5ターン制時代の名残（`turn-copy`、`execution-dock`等のクラス名や未使用selector）がある。名前から「ターン制」と誤認しない
8. 安全後退時のUI文言「命令を解除」と実際（pathのみ削除・任務は維持）が一致していない
9. `aiMessage` は更新・保存されるが、現在のfield-messageはevents中心で aiMessage を直接表示していない

## 18. 変更時に守る不変条件

1. 同シード・同設定・同コード → 同じ初期状態・同じ未来
2. 戦闘・勝敗は乱数ではなく決定的。表示乱数・粒子は計算に入れない
3. 同tickの損害は同時集計し、死亡済み部隊への誤攻撃・先手優位を作らない
4. 部隊・任務・セルはIDで参照。破棄済みオブジェクトをpathに保持しない
5. 生存兵員＋損失＝配備兵員、敵KPI合計＝敵損失、を損なわない
6. 進行中でも指示可能。自律任務は戦略目標・CPを勝手に決めない
7. モバイルで主要な指揮が数回のタップで完了する
8. 自動テストのPASSを実機QAや「面白さ」の証明と同一視しない
